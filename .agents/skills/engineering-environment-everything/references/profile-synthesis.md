# 프로파일 합성

사용자 표현, 확인한 작업 환경, 분야 지식을 [양식](../assets/profile-schema.md)의 각 축에 적용한다. 분야마다 산출물과 성공의 증거가 달라진다. 예를 들어 룰 검사 스크립트라면 대상 도구가 룰을 실행해 기대한 위반을 보고하는지가 증거다.

- 성공 증거(4번)와 금칙(5번)이 구체적으로 채워져야 한다. 관례나 검증 방법의 근거가 약하면 11번에 표시하고, 방향을 바꿀 수 있는 사항을 1~2개 확인한다.
- 도구가 없을 때 대안이 원래 검증을 얼마나 대신하는지 명시한다. 정적 검사로 실행 확인을 대신할 수 없다면 실행 검증은 별도로 남긴다.
- 여러 분야가 얽히면 10번에 각 경계와 접점의 검증 조건을 적는다. 각 분야의 제약과 증거를 환경 생성 단계에서 유지한다.
- 첫 루프 목표는 최소 산출물에서 확인 가능한 검증 경로까지 연결한다. 하드웨어와 드라이버처럼 접점이 있는 경우 작은 경로 하나를 끝까지 연결한다.

`harness/PROFILE.md` 초안에는 11개 항목과 가정을 유지한다. 사용자에게는 1, 4, 5, 9번을 계획·제약·검증 기준과 함께 요약해 한 번 확인받는다. 검토 단계에서 멈췄다면 `PROFILE.md`만 있는 상태로 다시 이어갈 수 있다.
