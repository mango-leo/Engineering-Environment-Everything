# Engineering Environment Everything

사용자 용어로 작업을 규정하고 조사한 근거로 구현 계획과 검증 코드를 만든다. 분야별 고정 분류표를 두지 않는다. 작업과 상태의 원본은 대상 프로젝트의 `harness/`다.

## 1. 상태 확인과 조사

기존 환경은 `AGENT.md`, `PROTOCOL.md`, `STATE.json`과 최신 결과·루프 기록을 읽는다. 진행 중인 실행의 마감 시각과 회차를 보존한다. PROFILE만 있으면 계획 초안부터 이어간다. v1 환경은 [환경 생성 규약](references/harness-generation.md)에 따라 이전한다.

새 요청은 [입력 규약](references/intake.md), [조사 규약](references/research.md)을 따른다. 목표·실행 대상·제약을 바꿀 정보만 최대 세 가지 묻고 파일·도구를 먼저 조사한 뒤 필요한 분야 지식을 검색한다.

## 2. 계획·제약·검증 환경 구성

[실행 규약](references/loop-protocol.md)의 모델 배정에 따라 높은 추론 수준의 계획 모델이 [프로파일](references/profile-synthesis.md)의 11개 축을 채운다. [환경 생성 규약](references/harness-generation.md)과 [검증 계약](references/checker-contract.md)에 따라 준비 명령과 준비 검사, 구현 계획, 요구사항별 PASS/FAIL 판정 코드와 정상·실패 예제를 작성한다. 도구가 아직 없어 실행하지 못하는 검사도 코드와 기준을 이 단계에서 완성한다.

계획·가정·금칙·완료 기준·예상 시간·60분 기본 제한을 함께 보여 주고 한 번 확인받는다. 이미 승인한 사용자의 권한은 유지한다.

## 3. 승인된 자동 실행

사용자가 승인하면 [실행 규약](references/loop-protocol.md)에 따라 계획과 판정 코드를 고정한다. 준비 검사와 필요한 설치·설정을 별도 단계에서 끝낸 뒤 정상·실패 예제로 검증기를 교정한다. 준비와 교정이 완료되면 낮은 추론 수준의 모델에 구현을 넘긴다. 구현 모델은 제품만 수정하며 실행기의 실패 증거를 바탕으로 보강한다.

호스트가 지원하면 가벼운 모델에 압축한 실행 요약을 보내 감시한다. 지원되지 않는 기능은 로그·시간·무진전 판정으로 대체한다. 최종 PASS는 공통 실행기의 전체 검증 결과로만 판단한다.

## 4. 완료 또는 중단 보고

[보고 양식](references/report-format.md)을 사용한다. 완료 시 전체 검증 증거를 제시한다. 시간 초과·외부 차단·무진전·제약 충돌 시 완료한 것, 진행하던 것, 남은 검증과 재개 지점을 저장하고 사용자 결정을 요청한다. 시간 제한은 사용자 요청에 따라 언제든 수정한다.
